# v0.1 Scope and Boundary

This document defines the scope, non-goals, adoption boundary, review expectations,
and non-canon posture for the **v0.1** release of Agent Control Plane Patterns.

It is the authoritative reference for what v0.1 is, what it is not, and how it
should be consumed until a later reviewed governance path supersedes it.

## Status

**Candidate.** v0.1 is an exploratory public seed release. Nothing in v0.1 is a
universal standard, a product, or an adopted specification. All artifacts are
candidate material pending review.

## Scope

v0.1 defines the **minimum viable packet** for describing agent control-plane
patterns as version-controlled, reviewable, testable, auditable, and
agent-operable source material.

In scope for v0.1:

- A clear **definition** of agent control-plane architecture as a domain.
- A set of **principles** governing public/private boundaries, provenance, and
  reviewability.
- A **prior-art** survey of public control-plane patterns and the adjacent
  ecosystem (Kubernetes, Operator Framework, Crossplane, Istio, Knative, AWS
  ACK, Cluster API, and supporting tooling).
- A **minimal JSON schema** (`schemas/agent-control-plane-patterns-v0.1.json`)
  describing a control-plane packet.
- A **valid example** and **fixtures** (one valid, one invalid) that exercise
  the schema.
- A **receipt** template that records what was produced, why, and under what
  authority.
- This **boundary document**, which sets review and adoption expectations.

Out of scope for v0.1 (deferred to later versions):

- Adoption criteria and governance process.
- Automated validation tooling and CI checks.
- Reviewed/adopted examples beyond candidate examples.
- A registry or catalog of packets.
- Runtime behavior, controllers, or any executable implementation.
- Multi-version compatibility guarantees.

## Non-goals

- This repo is **not** a universal standard.
- This repo **does not** claim ownership of the broader field or its
  terminology.
- This repo **does not** canonize any vendor-specific concepts (including
  HUMMBL, BaseN, or Ownward concepts) unless explicitly marked and audited.
- This repo **must not** include private, internal, or secret operational
  content.
- v0.1 **does not** define a wire protocol, an API, or a runtime contract.

## Adoption boundary

v0.1 is **reference material only**. Consumers may:

- Read, copy, fork, and adapt the schema and examples.
- Use the vocabulary and prior-art survey as a shared reference point.
- Propose changes via issues and pull requests.

Consumers may **not**:

- Treat v0.1 as an adopted specification or standard.
- Claim conformance to v0.1 in a product without an explicit, reviewed
  conformance path (which does not yet exist).
- Reuse the schema for private/secret operational content inside this
  repository.

## Review expectations

- All v0.1 artifacts are **candidate** until reviewed.
- Review is expected to happen through pull requests against this repository.
- A reviewed governance path (with criteria, maintainers, and an adoption
  process) is a **later** roadmap item, not part of v0.1.
- Until that path exists, no artifact in v0.1 should be described as "adopted",
  "standard", or "canonical".

## Non-canon posture

v0.1 is explicitly **non-canon**. It is a starting point for discussion, not a
final word. The vocabulary, schema, and examples reflect a candidate reading of
public prior art and may change without notice in later versions.

Nothing in v0.1 is endorsed as the definitive model for agent control planes.
The intent is to make a small, reviewable starting artifact that later versions
can refine, replace, or reject.

## Required packet pieces

A v0.1 control-plane packet consists of the following required pieces, all of
which must be present and consistent:

1. **Schema** — `schemas/agent-control-plane-patterns-v0.1.json`
   - Defines the structure of a control-plane packet.
   - Required top-level fields: `schemaVersion`, `packetStatus`,
     `controlPlaneManifest`, `authority`, `controlPlaneContract`,
     `receiptRequirements`.

2. **Example** — `examples/control-plane-packet-v0.1.example.json`
   - A single, complete, valid example packet that satisfies the schema.
   - Demonstrates intended usage and is candidate, not adopted.

3. **Fixtures**
   - `fixtures/valid/control-plane-packet-v0.1.valid.json` — a packet that
     **must** validate against the schema.
   - `fixtures/invalid/control-plane-packet-v0.1.invalid.json` — a packet that
     **must fail** validation (used to demonstrate required-field enforcement).

4. **Receipt** — `receipts/agent-control-plane-patterns-v0.1-packet-receipt.md`
   - Records what was produced, the authority under which it was produced, the
     non-canon posture, and links to the artifacts above.

5. **Boundary** — this document (`docs/v0.1-boundary.md`).

6. **Prior art** — `docs/prior-art.md`.

A v0.1 packet is considered **complete** only when all six pieces are present
and mutually consistent.
